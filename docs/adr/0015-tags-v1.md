# ADR 0015: Tags v1 with inline editing and on-demand exact filtering

- Status: accepted
- Date: 2026-08-10

## Decision

The Windows editor exposes the existing NoteDraft tag list directly below the
title. Enter or a Chinese/ASCII comma confirms input, an optional leading `#` is
removed, and each chip can be removed independently. Core's frozen NoteDraft
normalization continues to trim empty values, remove exact duplicates, and sort
the resulting strings before persistence or Revision creation.

Tags remain ordinary note content. They use the existing Draft autosave,
Revision DAG, encrypted remote object, conflict resolution, Portable Export, and
Portable Import paths. Tags v1 adds no table, migration, Event type, or remote
object layout.

## Filtering

Core filters with an exact value comparison over `json_each(tags_json)`. This
keeps `work` distinct from `workshop` and avoids interpreting tag text as SQL or
FTS syntax. Tag filtering and FTS5 title/body search can be active together; a
note must satisfy both conditions. Deleted notes are excluded.

The tag directory contains exact tag values and active-note counts. It is
aggregated only after the user opens the tag filter dialog, never during startup.
The selected tag itself is lightweight Workspace state. Creating a note while a
tag is selected seeds that tag into the new Draft so the note stays visible.

## Responsiveness and failure boundary

Tag edits enter the same immediate coalescing save queue as title and body edits.
Filtering is a bounded local SQLite query and never performs network I/O. Query
generations prevent an earlier search or tag request from replacing newer
combined results. A filter error leaves the editor and persisted Draft intact.

## Exclusions

Tags v1 does not add nested tags, colors, aliases, case folding, bulk retagging,
automatic suggestions, or a global tag-management screen. Exact tag spelling is
preserved across devices.

## Verification

Core tests cover exact matching, counts, deleted-note exclusion, and tag/search
intersection. Windows controller and widget tests cover autosaved tag editing,
on-demand filter loading, visible filter state, combined queries, and active-tag
inheritance for a new note.
